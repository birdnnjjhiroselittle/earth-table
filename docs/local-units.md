# 小さな単位から始める：都市・離島・小国と、共有地の悲劇

[English](local-units.en.md) | **日本語**

**小さく閉じた単位で最適化し、つなぎ目にだけ値段とルールを置く。そうすれば局所最適は悲劇にならず、全体の最適への部品になる。**

---

## 1. なぜ大国ではなく、小さな単位から始めるのか

大国は、地域・産業・制度が複雑すぎて、最初の実証の場には向きません。都市・離島・小国から始めます。

| 単位 | 強み | 例 |
|---|---|---|
| **離島** | 出入りが港と空港に限られ、食べものの流れをほぼ全部測れる。物流費が高いので、ロスを減らす価値が大きい | 日本の離島、太平洋の島国 |
| **都市** | 人が密集していて、プレイヤーもお店も多い。人の流れのデータがある | 中規模の地方都市 |
| **小国** | 国の政策まで実証できる。輸入に頼る国が多く、食料安全保障と直結する | シンガポール（食料の大部分を輸入）、太平洋の島国 |

太平洋の島国では、輸入された加工食品への依存が進み、肥満率が世界で最も高い国々が集まっています。**食品ロスと健康を同時に解く** 実証の場として、特に意味があります。

---

## 2. 何を最適化するか：ゲーム × 物流 × 人流

| 対象 | 最適化すること | 例（離島の場合） |
|---|---|---|
| **物流** | 船・トラックの便、積む量、冷蔵倉庫の容量 | 台風で欠航しそうなら事前に多めに運ぶ。欠航がなければ余りを島内で回す |
| **人流** | 観光客・住民の動き、買い物の移動 | 観光客の予約数を、ホテル・飲食店の仕入れに反映。観光のピーク後の余りを減らす |
| **ついで配送** | すでにある移動に配送を乗せる | 通勤・通学・路線バスのついでに、おすそ分けを届ける |
| **ゲーム** | クエストの出し方 | 余りが出る場所と時間に合わせ、近くのプレイヤーにレスキュー・クエストを出す |

---

## 3. 局所最適は、共有地の悲劇になるか

**共有地の悲劇** は、みんなで使う資源に値段もルールもないとき、各自が自分の得だけを考えて使い尽くしてしまう現象です（ハーディン、1968年）。

### 悲劇は「全体」ではなく「継ぎ目」で起きる

食品ロスの削減そのものは、ほとんど **全員の得** です。ある町がロスを減らすと、世界の市場から買う量が減り、他の町の食べものも安くなります（良い外部性）。

しかし、単位と単位の **継ぎ目** では、局所最適が他の単位に損を押しつけることがあります。

| 危険 | 何が起きるか | 実例・類似例 |
|---|---|---|
| **① ロスの押し出し** | 島が「完璧な野菜」しか輸入しなくなり、規格外品は島の外の農家で捨てられる。島の数字だけが良くなる | 境界の外の損失が見えない |
| **② 買い占め** | 予測の上手な都市が不作の年に先回りして確保し、近くの町が足りなくなる | 2008年・2022年の食料危機での輸出禁止。各国が自国を守った結果、世界の値段が上がった |
| **③ 共有の物流の奪い合い** | 限られたフェリーの枠や冷蔵倉庫を、ある町が独占する | 共有インフラの混雑 |
| **④ 人の集中** | ゲームの報酬が大きい場所にプレイヤーが殺到し、混雑や迷惑が起きる | 位置情報ゲームでの人の殺到 |
| **⑤ 共有の自然資源** | 島どうしが同じ漁場で、それぞれ獲れるだけ獲る | 漁業資源の枯渇 |

---

## 4. 継ぎ目を直す5つの方法

### ① 共有の資源にだけ「影の価格」を付ける

悲劇の原因は、共有資源の値段がゼロになっていることです。
単位をまたいで共有する資源（フェリーの枠・冷蔵倉庫・漁業資源・CO2）**にだけ** 影の価格か上限を付け、それ以外は各単位が自由に最適化します。

```
各単位 u：   自分の目的 − Σ（共有資源の影の価格 × 自分の使用量） を最大化
調整役：     共有資源の使用量の合計が上限を超えたら、影の価格を上げる
```

$$
\lambda_{c} \;\leftarrow\; \max\Bigl(0,\ \lambda_{c} + \alpha \bigl(\textstyle\sum_u \text{使用量}_{u,c} - \text{上限}_c\bigr)\Bigr)
$$

こうすると、**局所最適の合計が、全体の最適と一致します**（双対分解。くわしくは [統合最適化](https://github.com/birdnnjjhiroselittle/tabemono-subete-ai/blob/main/docs/integrated-optimization.md)）。

### ② 境界の外まで数える

スコアは、単位の中のロスだけでなく、**仕入れ先と送り先で生じたロス** まで含めて数えます。ロスを外へ押し出しても得になりません。

```
単位のロス ＝ 中のロス ＋ 仕入れ先で、自分の注文のせいで出たロス ＋ 送り先で出たロス
```

### ③ 入れ子の自治（オストロムの原則）

オストロムは、地域の人が共有資源を自分たちで上手に管理してきた事例を研究し、ノーベル経済学賞を受けました。その原則をそのまま使います。

| オストロムの原則 | この構想での形 |
|---|---|
| はっきりした境界 | 島・都市・小国という単位 |
| 地域に合ったルール | 各単位が自分のルールを決める |
| 当事者が参加してルールを作る | 住民・お店・農家・漁師が1人1票 |
| 見守り（モニタリング） | ロス・物流・共有資源の使用量を公開 |
| 段階的な罰則 | 押し出し・買い占めは、まず警告、次に減点 |
| 争いの解決の場 | 単位どうしの話し合いの場 |
| 自治の権利が認められる | 国や大企業が上から命令しない |
| **入れ子の組織** | 単位 → 隣どうしの連合 → 地域の連合 → 世界、と入れ子でつながる |

### ④ 危機のときの約束

平時のうちに、

- 「備蓄は決めた量まで」
- 「不作・欠航のときは分け合う」
- 「輸出を止めない」

という相互応援協定を結んでおきます。日本の自治体どうしの災害時応援協定と同じ考え方です。

### ⑤ くり返しのゲームと評判

一度きりの取引では裏切りが得になりますが、何度もくり返す関係では協力が得になります（アクセルロッドの研究）。
「どれだけ隣の単位を助けたか」を **評判** として見えるようにし、評判の高い単位ほど、危機のときに助けてもらいやすくします。

## 5. ゲームにすると：「島と都市のリーグ」

| 要素 | 内容 |
|---|---|
| **チーム** | 各島・都市・小国がチーム。住民がプレイヤー |
| **個人の成績** | ロス削減、健康（野菜の摂取・歩数）、物流のCO2 |
| **協力の成績** | 隣を助けた量、共有資源を上限内で使えたか |
| **順位** | 「自分の成績 ＋ 協力の成績」で決まる。押し出し・買い占めは減点 |
| **共同イベント** | 台風で港が閉じる、不作、パンデミック。単位どうしが助け合わないと乗り切れない |
| **協定の練習** | ゲームの中で協定を結んでみて、うまくいった協定を現実の島・都市どうしで結ぶ（知恵の橋） |

### 人流への配慮
- クエストの報酬は、人が集まりすぎると自動で下がる（混雑にも影の価格を付ける）
- 住宅街・私有地・危険な場所にはクエストを出さない
- 観光客にもクエストを出し、観光のピーク時の余りを観光客自身が救えるようにする

## 6. 最初の実証の候補

| 段階 | 単位 | 理由 |
|---|---|---|
| 1 | **離島1つ** | 流れを全部測れる。結果が分かりやすい |
| 2 | **近くの離島どうし** | 共有の船便・漁場で、継ぎ目の問題と対策を試せる |
| 3 | **地方都市1つ** | 人流とゲームの規模を試せる |
| 4 | **小国** | 国の政策・輸入・健康政策まで含めて試せる |
| 5 | 単位どうしの連合 | 入れ子の自治で広げる |
